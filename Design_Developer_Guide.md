# ROCPD to Babeltrace2 Plugin to TraceCompass: Design and Developer Guide

This document provides developers with a comprehensive explanation of the design flow for converting ROCPD databases (generated by `rocprofv3`) into CTF traces, making them consumable by Trace Compass through the Babeltrace2 plugin. It highlights the core design, where to make changes in the Babeltrace2 plugin (`bt_plugin_rocm.py`), how this file works, and the supported features. It also explains the integration on the Trace Compass side in the **rocpd_support** branch.

---

## High-Level Workflow

1. **rocprofv3 Data Collection**
   - `rocprofv3` generates profiling and tracing results stored in a **ROCPD SQLite database**.

2. **Babeltrace2 Plugin (ROCPD Plugin)**
   - The Babeltrace2 plugin (`bt_plugin_rocm.py`) reads the ROCPD database and **converts it into a CTF trace**.
   - This enables interoperability with CTF tooling and visualization platforms.

3. **Trace Compass Import**
   - Trace Compass (with the incubator `rocpd_support` branch) imports the generated CTF traces.
   - Provides custom analyses for ROCm profiling and tracing data.

---

## Babeltrace2 Plugin: `bt_plugin_rocm.py`

The plugin is located in [Babeltrace2-ROCpd-Plugin](https://github.com/ammarwa/Babeltrace2-ROCpd-Plugin). This is the primary file that developers must modify when extending support.

### Responsibilities
- **Database Reader**: Opens and queries the SQLite database generated by `rocprofv3`.
- **Event Mapping**: Maps ROCPD tables (API calls, kernels, memory copies, etc.) into Babeltrace2 event classes.
- **CTF Conversion**: Converts queried results into valid CTF trace events.

### Key Sections to Modify
1. **Database Connection Logic**
   - Code handling SQLite connections and queries.
   - Extend this section if new tables or schema updates are introduced in ROCPD.

2. **Event Class Definitions**
   - Located in functions mapping DB rows into CTF events.
   - Developers add or modify event classes to represent new ROCm activity types.

3. **Trace Iterators**
   - Responsible for streaming events from DB → Babeltrace2.
   - Key point to add filtering, timestamp adjustments, or event ordering logic.

### Supported Internally
- API Call Tracing (HIP, HSA, OpenMP)
- Kernel Dispatch Events
- Memory Copy Events
- Process and Thread ID associations
- Timestamp synchronization across event types

## Trace Compass Integration

The Trace Compass integration is implemented in the [rocpd_support branch](https://github.com/ammarwa/org.eclipse.tracecompass.incubator/tree/rocpd_support) of the **Trace Compass Incubator** repository.

### Location of Changes
The modifications are visible in the [pull request #2](https://github.com/ammarwa/org.eclipse.tracecompass.incubator/pull/2/files).

### Responsibilities
- **CTF Analysis Extension**: Adds support for interpreting ROCm-specific events generated by the Babeltrace2 plugin.
- **Views and Analyses**: Provides timelines, state system views, and analysis modules for ROCm events.

### Files Modified
- **Analysis Modules**: Define how ROCm events are analyzed.
- **Trace Type Definition**: Registers the new ROCm CTF trace type.
- **UI Components**: Add views to display kernel execution, memory copies, and API call timelines.

## Developer Workflow for Extending Support

1. **ROCPD Database Update**
   - Ensure that new tracing/profiling information is being written into the SQLite DB by `rocprofv3`.

2. **Babeltrace2 Plugin Update**
   - Modify `bt_plugin_rocm.py`:
     - Extend DB query logic.
     - Add new event mappings.
     - Validate event timestamps and metadata.

3. **Trace Compass Update**
   - Extend the **rocpd_support** branch:
     - Add support for new events in the analysis modules.
     - Register new trace types or event attributes if needed.
     - Update UI components to visualize the new data.
    - For non-API traces:
      - Add a handler class under `analyses/org.eclipse.tracecompass.incubator.gpu.core/src/org/eclipse/tracecompass/incubator/gpu/core/handlers`.
      - Register and use the handler in `analyses/org.eclipse.tracecompass.incubator.gpu.core/src/org/eclipse/tracecompass/incubator/gpu/core/analysis/GpuCallStackAnalysis.java`.
    - For UI updates:
      - Update or extend the relevant classes in `analyses/org.eclipse.tracecompass.incubator.gpu.core/src/org/eclipse/tracecompass/incubator/gpu/core/handlers` to surface the new traces in the UI.

4. **Validation**
   - Run `rocprofv3` to generate new ROCPD DB.
   - Use the Babeltrace2 plugin to convert DB → CTF.
   - Import CTF trace into Trace Compass and verify correctness.

## Collect, Convert, and View a ROCPD Trace

- Prerequisites:
  - rocprofv3 and ROCm runtime installed
  - Babeltrace 2 installed and the ROCPD Babeltrace2 plugin available
  - Java and Eclipse IDE for Eclipse Committers installed: https://www.eclipse.org/downloads/packages/

1) Generate a ROCPD database with rocprofv3
- Example:
  ```rocprofv3 --runtime-trace --kernel-trace --memory-copy-trace --memory-allocation-trace -d example-trace-out -- ./rocm-systems/projects/rocprofiler-sdk/build/bin/hip-in-libraries```
- Result:
  - A SQLite DB (typically named <run_id>_results.db) inside example-trace-out

2) Convert the ROCPD DB to a CTF trace using Babeltrace2
- Example:
  ```babeltrace2 --plugin-path=. --component source.rocm.RocmSource --params='db-path="../../Downloads/2341696_results.db"' --component sink.ctf.fs --params='path="demo_ctf_trace"'```
- Notes:
  - Adjust --plugin-path to where the ROCPD Babeltrace2 plugin is located
  - Update db-path to your generated results.db
  - The CTF output will be written to demo_ctf_trace

3) Set up Trace Compass (developer workflow)
- Clone the repos:
  - Incubator (rocpd_support branch): https://github.com/ammarwa/org.eclipse.tracecompass.incubator/tree/rocpd_support
  - Core: https://github.com/ammarwa/org.eclipse.tracecompass
- In Eclipse:
  - Import both repositories as existing projects
  - In org.eclipse.tracecompass.incubator.target, open tracecompass-incubator-master.target and click Reload Target Platform
  - Run As → Eclipse Application to launch a Trace Compass runtime workbench

4) Open and inspect the CTF trace
- In the launched Trace Compass:
  - Import the generated CTF folder (demo_ctf_trace) and explore the `views/GPU Timeline`

5) Alternative: run the Trace Server and view in VS Code/Theia
- In Eclipse:
  - Open org.eclipse.tracecompass.incubator.trace.server.product → traceserver.product and Run
- In VS Code:
  - Install the Trace Viewer and Trace Server extensions from the Marketplace, then open the CTF trace
- Alternative: In Theia:
  - Install/enable the Theia Trace Viewer and open the CTF trace

Tips:
- Ensure you use Babeltrace 2 (bt2) and the ROCPD plugin is discoverable via --plugin-path
- If traces are empty, verify rocprofv3 privileges and that your workload exercised runtime, kernels, and memory operations

---

## Summary

- **`bt_plugin_rocm.py`** is the heart of the ROCPD → CTF conversion logic.
- Developers primarily modify:
  - DB query sections
  - Event class mappings
  - Iteration/streaming logic
- **Trace Compass `rocpd_support` branch** adds the consumer side for the CTF trace.
- Together, they form a pipeline: **ROCPD DB → Babeltrace2 Plugin → CTF → Trace Compass**.

---

This design enables continuous extension: whenever `rocprofv3` supports new data, developers only need to add support in `bt_plugin_rocm.py` and extend Trace Compass analyses accordingly.
